## 고객 여정

```
① 가입 (이메일 또는 데모 계정) → 언어 자동 감지
      ↓
② 채팅 온보딩 (약 3분): 동의 → 기본 정보 → 방한 일정 → 피부 상황 → 과거 시술 → 안전 정보 → 선호·예산
   화면 오른쪽(모바일은 상단 접힘)에 "내 에이전트 카드"가 실시간으로 채워진다
      ↓
③ 에이전트 생성 완료 → 홈: "무엇을 받고 싶으세요?"
      ↓
④ "リジュラン受けたい" 한마디 → 고객 에이전트가 조건 카드로 정리
   (시술 · 용량 · 예산 · 지역 · 언어 · 날짜) → 빠진 것만 되묻기 → [이 조건으로 찾기]
      ↓
⑤ 진행 화면: 에이전트 대화가 사람이 읽는 문장으로 실시간 표시
   "플랫폼에 맞는 병원을 물어봤어요" → "병원 3곳에 견적을 요청했어요" → "플랫폼이 가격을 검토했어요"
      ↓
⑥ 견적 비교: 병원별 총액, 단위가격, 용량, 포함 항목, 가능 시간, 판정 라벨(적정 / 높음 / 용량 부족 / 판정 불가)과 근거
      ↓
⑦ 선택 → [예약 요청] → 대행 병원이면 "병원 확인 대기" → 확정 알림
      ↓
⑧ 시술 당일 (D0): "얼마 내셨어요? 몇 cc 받으셨어요?" 3초 기록 → 플랫폼으로 결과 전송
      ↓
⑨ D7 · D30 체크인 (P1) → 만족도·다운타임 실제 → 다음 회차 제안 → 다음 방한 계획
```

### 한국 여성 여정 (데이터 공급)

```
시술 직후 3초 기록 (시술 · 용량 · 병원 · 가격 · 날짜, 선택: 영수증 사진·별점)
→ 다음 회차 계산 → 알림 (계속 / 쉬기 / 그만)
→ 기록 공유 동의 시 익명 처리되어 플랫폼 가격 분포의 표본이 된다
```

## 병원 여정

```
[대행 운영 단계: 병원은 아무것도 안 해도 된다]
운영자가 병원 문자·공개 가격표로 대행 병원 에이전트 생성 → 견적 요청에 대행 에이전트가 참고가로 응답
→ 예약 요청은 운영자가 병원에 전화·카톡으로 확인 후 확정

[인수 단계]
① 병원 가입 → "이미 Pibu가 대행 운영 중인 에이전트가 있습니다" 안내
② 채팅 온보딩 (약 10분): 기관 정보 → 등록 서류 → 의료진 → 언어 → 시술 메뉴(가격표 업로드 시 자동 추출) → 예약 운영 → 수수료 동의
③ 대행 데이터와 병원 입력의 차이를 표로 보여주고 확정
④ Agent Card 미리보기 → [내 에이전트로 운영 시작] → 운영 모드가 "직접 운영"으로 바뀐다
⑤ 병원 콘솔에서 요청함·메뉴·예약 시간 관리, 집계 피드백 확인
⑥ (P2) 병원이 자기 도메인에 같은 Agent Card를 호스팅 → 플랫폼 레지스트리 URL 갱신
```

## 운영자 여정

```
매일: 대행 응답 큐 처리 (예약 확인 전화) → 데이터 신선도 낮은 대행 병원 갱신
결과 신호 확인 → 플랫폼 에이전트가 제안한 연결 규칙 검토 → 승인 / 반려
규칙 적용 후 지표 변화 확인 (P1)
```

## 데모 핵심 장면 (3분)

1. Yuki가 일본어 채팅으로 온보딩, 오른쪽 에이전트 카드가 채워진다.
2. "リジュラン受けたい" → 조건 카드 → 진행 화면에 A2A 대화가 흐른다.
3. 견적 비교에서 민트피부과의 "1cc 이벤트"에 **용량 부족** 라벨, 아라의원에 **견적 대비 실결제 상승 이력** 경고.
4. 서울글로우의원 예약 → 확정.
5. 운영 콘솔: 결과가 쌓이자 플랫폼 에이전트가 "아라의원 일본 고객 매칭 제외" 규칙을 제안 → 운영자 승인 → 같은 요청을 다시 보내면 아라의원이 빠진다.
