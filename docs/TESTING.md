# 흐름 검사 (언제 무엇을 돌리나)

"주소가 200인가"만으로는 화면 흐름의 버그를 못 잡는다. 대화 창에서 언어 칩을 눌렀더니 페이지가 통째로 이동해 대화가 사라진 문제(2026-10-24)가 그랬다. 그래서 **실제 브라우저로 눌러 보는 검사**(`e2e/*.e2e.ts`, Playwright)를 따로 둔다.

## 무엇을 보나

- 눌렀을 때 페이지가 갑자기 이동하거나 대화가 끊기지 않는지 (주소, 에이전트 창, 대화 내용)
- 처음 방문 투어와 에이전트 창이 같이 뜨고, 한 번 본 뒤에는 다시 안 뜨는지
- 콘솔 에러, 페이지 에러, 4xx/5xx 응답, 실패한 요청이 하나도 없는지 (글꼴 404 한 건만 알려진 예외)
- 키보드: Esc로 닫히고 포커스가 돌아오는지

## 언제 돌리나

| 시점 | 명령 | 비고 |
| --- | --- | --- |
| 커밋 전 | `npm run typecheck && npm test` | 빠름 |
| 화면이나 흐름을 건드린 PR 올리기 전 | `npm run build && npm run test:e2e` | 약 1분 |
| 모든 PR과 `main` 푸시 | CI `ci` 워크플로가 자동 | `build` 다음 단계 |
| `main` 머지 후 배포 확인 | `E2E_BASE_URL=https://pibook-app.vercel.app npm run test:e2e` | 프로덕션 별칭에 직접 |
| 버그를 하나 찾았을 때 | **고치기 전에** 실패하는 케이스를 `e2e/`에 먼저 추가 | 같은 버그의 재발을 막는 유일한 방법 |

## 새 케이스를 쓸 때

- 흐름이 하나 늘면 케이스도 하나 늘린다. 눌러 본 결과(주소, 창, 대화)를 단언한다.
- 고친 뒤에는 고침을 일부러 되돌려서 케이스가 **실제로 실패하는지** 한 번 확인한다. 통과만으로는 케이스가 쓸모 있는지 알 수 없다.
- 사람이 직접 눌러 보는 건 새 화면을 처음 만들 때 한 번이면 충분하다. 그 뒤는 케이스로 남긴다.

## 아직 덮지 못한 곳

온보딩 전체(약관, 날짜, 예산 등 위젯 단계)를 끝까지 걷는 케이스는 없다. 지금은 언어 선택 단계까지와 랜딩의 모든 진입점(힌트 칩, 토픽 카드, 입력창, 투어, 창 열기, 크게 보기, 닫기)을 덮는다.
